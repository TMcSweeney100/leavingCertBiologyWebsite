Rewritten at the end of every session: where things stand, what's half-done, what's waiting on a human. Anything permanent goes elsewhere (`docs/ARCHITECTURE.md` for how the code and hosts work, `docs/PILOT-ROADMAP.md` §2–§3 for decisions, the plans for per-task deviations). The live BiPi site's final handoff is archived at `docs/archive/bipi-site/HANDOFF.md`; its open items (Katelyn's copy sign-offs, print page count) still stand.

**Standing rule (16 Sep 2026):** `docs/ARCHITECTURE.md` describes the code as built. When a session changes anything it describes (a filter, a pattern, an env var, a file's job), it fixes that section in the same commit, and at the end of the session checks it for anything else the session made false. A wrong map is worse than none.

## Not done, and worth a follow-up

- **Two `UI-CHECKLIST.md` items were already missing and are still open.** Submit buttons don't change to a present-participle label while busy ("Signing in…"; they only disable), and a failed submit doesn't move focus to the alert. Both need a spec each.
- **Sign in stays enabled during a lockout.** D-1 draws it disabled, but the API returns the wait only as text in `detail` (roadmap §6.2 `/login` row). Disabling it would need a machine-readable retry time from `LoginThrottle`.
- **On phones, student rows wrap their buttons under the name.** "Issue reset code" plus "Remove" is wider than the space D-2 leaves beside a name at 390px. Pending rows fit as drawn.
- **`ComponentService.owned` checks the component's own owner filter and `ClassService.owned` independently (defense in depth, found reviewing 2D Task 7).** `ComponentScopeTest` proves the endpoints 404 correctly today, but a future regression that broke only `ComponentRepository.findOwned`'s owner filter wouldn't be caught by any current test unless `ClassService.owned` broke at the same time. Worth a test that isolates each check; not a defect and not blocking.
- **`TeacherItems`' `editing` and `retiring` local state are independent (found reviewing 2D Task 9).** A teacher editing one item's text or date who then retires a *different* item in the same stage has their in-progress edit silently discarded — no data corruption, just a lost unsaved draft, with no confirmation shown. Low risk, narrow edge case, worth a fast-follow fix.
- **The D-3 tick line has no date (found building 2E Task 8).** The pack draws "You ticked this · 2 Oct 2026"; the API's `studentItemSchema` (and the `item_tick` row behind it) carries no `done_at`, so the build says "You ticked this" without one rather than fabricate a date. Exposing it is a small, real backend change (`ItemTickRepository`/`ComponentViews` would need to read and return `done_at`) — worth doing as its own task rather than folding into a restyle.
- **Prompts don't open by default at 1140 (found building 2E Task 8, a known simplification).** D-3's NOTES draw them open by default on the laptop, collapsed at 390 (a per-breakpoint default on a native `<details>`, which has no CSS-only way to do that). Built collapsed at both widths for now — costs the laptop's spare room, changes nothing about reachability.
